# ODPS `default` schema 限定符修复说明（Docker 部署 / 最小 diff 版）

## 问题

Superset 为 ODPS(MaxCompute)自动生成的查询带 schema 限定符 `default`：

```sql
SELECT pm_name AS pm_name
FROM "default".v_monitoringoverduelist
WHERE NOT pt IS NULL
GROUP BY pm_name
LIMIT 10000
```

报错：

```
ODPS-0130131:[2,6] Table not found - table `default`.v_monitoringoverduelist cannot be resolved
```

去掉 `"default".` 前缀（裸表名）正常。

## 根因

ODPS SQLAlchemy 方言把 `default` 作为 `default_schema_name` 上报，Superset 据此在生成 SQL 时拼出 `"default".表`。但经典两层 ODPS 项目没有 `default` schema，后端解析不了 → `ODPS-0130131`。裸表名能跑是因为 ODPS 用连接默认 project 解析。

> 这是 ODPS 后端执行错误，不是 Superset 解析 / DML 拦截问题（sqlglot 对 `"default".表` 所有方言都能解析，已实测）。

## 为什么不用源码改法

部署是 Docker。容器里跑的是镜像内的 superset，仓库里改 `odps.py`/`models.py` 等源码**容器不会加载**（要么重建镜像、要么挂载覆盖文件，都不"最小 diff"）。因此采用**只改配置文件**的方案——配置一定会被容器加载。

## 修复方案（唯一改动：`superset_config.py`）

利用 Superset 的 `SQL_QUERY_MUTATOR` 钩子。它在**最终 SQL 下发前**统一改写，覆盖所有路径（物理表 chart / 虚拟数据集 / SQL Lab），`kwargs["database"]` 可按引擎定向处理。对 ODPS，用正则剥掉占位 schema 限定符 `default.`。

`sql_query_mutator_config.py` 即为本方案的完整内容，核心：

```python
import re
_ODPS_DEFAULT_SCHEMA_QUALIFIER = re.compile(r'["`]default["`]\s*\.')

def SQL_QUERY_MUTATOR(sql: str, **kwargs) -> str:
    database = kwargs.get("database")
    spec = getattr(database, "db_engine_spec", None)
    if spec is not None and getattr(spec, "engine", None) == "odps":
        sql = _ODPS_DEFAULT_SCHEMA_QUALIFIER.sub("", sql)
    return sql
```

- 只匹配**带引号**的 `"default".` / `` `default`. ``（Superset 生成的标识符都是带引号的），不误伤列别名 / 表别名。
- 只对 `engine == "odps"` 生效，不影响其它数据库。
- 实测你的 SQL：`FROM "default".v_monitoringoverduelist` → `FROM v_monitoringoverduelist`，其余不动。

### 触发确认（无需改 MUTATE_AFTER_SPLIT）

- ODPS `run_multiple_statements_as_one = False`，默认 `MUTATE_AFTER_SPLIT = False`。
- chart 异步路径在 `superset/sql/execution/executor.py:174` 以 `is_split=False` 调用 mutator，`is_split(False) == MUTATE_AFTER_SPLIT(False)` 成立 → **mutator 触发**，对整条 SQL 改写后重新解析下发。
- 所以默认配置即可，**不用**改 `MUTATE_AFTER_SPLIT`。

## Docker 部署步骤

1. 找到实际加载的配置文件路径（在跑 superset 的容器里）：
   ```bash
   docker exec <superset容器名> sh -c 'echo $SUPERSET_CONFIG_PATH'
   ```
   通常形如 `/app/pythonpath/superset_config.py`，且由 docker-compose 从宿主机 `./superset_config.py` 挂载。

2. 编辑宿主机上对应的 `superset_config.py`：
   - 若已有 `SQL_QUERY_MUTATOR`：在函数内、`return sql` 前插入 ODPS 处理段。
   - 若没有：把 `sql_query_mutator_config.py` 里的 `import re` + 正则 + `SQL_QUERY_MUTATOR` 整段追加进去。
   - 若宿主机根本没有自定义配置文件：新建 `superset_config.py`，内容为本仓库 `superset/config.py` 末尾需要的项 + 本 mutator，并在 docker-compose 里挂载 + 设 `SUPERSET_CONFIG_PATH`（这一步需要改 compose，非纯最小 diff；多数部署已有自定义配置文件，走前两种即可）。

3. 重启容器（无需重建镜像）：
   ```bash
   docker compose restart superset          # 服务名按你的 compose 来，可能还有 worker:
   docker compose restart superset superset-worker
   # 或直接：
   docker restart <superset容器名>
   ```

4. 回到出问题的图表重新运行。

## 验证（无需跑 python）

- 在 SQL Lab 运行该查询，结果面板会显示 **Executed SQL**；确认 FROM 已无 `"default".` 前缀。
- 图表不再报 `ODPS-0130131`，数据正常返回即为成功。

## 回滚

从 `superset_config.py` 删掉 `SQL_QUERY_MUTATOR`（或恢复原函数），重启容器即可。
